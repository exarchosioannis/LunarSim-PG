# Output format

LunarSim-PG produces two distinct artifact families:

- terrain-generation packages under `Tools/Terrain_Generation/`;
- Unreal dataset runs under `Saved/Datasets/`.

This page describes both and distinguishes offline files from ROS-only streams.

## Dataset directory layout

A representative enabled run is:

```text
Saved/Datasets/
├── current_dataset_run.txt
└── YYYY-MM-DD_HH-MM-SS/
    ├── Maps/
    │   ├── occupancy_map.pgm
    │   ├── occupancy_map.yaml
    │   ├── elevation_map.csv
    │   ├── elevation_map.yaml
    │   ├── elevation_map_preview.pgm
    │   ├── slope_map.csv
    │   ├── slope_map.yaml
    │   └── slope_map_preview.pgm
    └── Session_001/
        ├── manifest.csv
        ├── session_metadata.json
        ├── Images/
        │   ├── RGB/<frame_index>.png
        │   ├── Depth/<frame_index>.png
        │   ├── Segmentation/<frame_index>.png
        │   ├── BoundingBoxes/<frame_index>.csv
        │   └── SegmentationInfo/
        │       ├── segmentation_info.json
        │       └── segmentation_classes.json
        └── Navigation/
            ├── rover_gt_trajectory_ros.csv
            ├── left_camera_gt_trajectory_ros.csv
            └── right_camera_gt_trajectory_ros.csv
```

Only enabled modalities are populated. `Session_002` and later directories are
created for later capture intervals in the same Play In Editor run.

## Offline modalities

| Output | Format / encoding | Units | Frame | Naming | Synchronization key |
| --- | --- | --- | --- | --- | --- |
| Ground-truth RGB | PNG | Pixel values | Left/reference camera optical frame | `<frame_index>.png` | Manifest frame index and timestamp |
| Depth | PNG with depth packed into RGB | Millimeters after decoding | Ground-truth camera view | `<frame_index>.png` | Manifest frame index and timestamp |
| Segmentation | Color-coded PNG with JSON legends | Class color | Ground-truth camera view | `<frame_index>.png` | Manifest frame index and timestamp |
| Bounding boxes | CSV | Pixels | Ground-truth image plane | `<frame_index>.csv` | Manifest frame index and timestamp |
| Rover trajectory | CSV pose | Meters, quaternion | `map -> base_link` | Fixed file name | Frame index and timestamp columns |
| Left camera trajectory | CSV pose | Meters, quaternion | `map -> left_camera_link` | Fixed file name | Frame index and timestamp columns |
| Right camera trajectory | CSV pose | Meters, quaternion | `map -> right_camera_link` | Fixed file name | Frame index and timestamp columns |
| Camera calibration | JSON fields in session metadata | Pixels, degrees, meters | Left/right optical cameras | `session_metadata.json` | Session-wide |
| Occupancy | PGM + YAML | 0.40 m/cell | `map` | `occupancy_map.*` | Run-level snapshot |
| Elevation | CSV + YAML + preview PGM | Meters | `map` | `elevation_map.*` | Run-level snapshot |
| Slope | CSV + YAML + preview PGM | Degrees | `map` | `slope_map.*` | Run-level snapshot |

The offline ground-truth camera writes one RGB/depth/segmentation/bounding-box
view. Left/right stereo RGB images and IMU samples are ROS-only unless recorded
in a rosbag.

“Segmentation” is the implementation-accurate term. A fixed semantic class set
or instance-segmentation contract is **Not yet verified**; use the legends
written for the session rather than assuming class names.

## Manifest

`manifest.csv` is the per-frame index:

```text
session_id,frame_index,timestamp_sec,rgb_path,depth_path,segmentation_path,bounding_boxes_path,rover_trajectory_file,left_camera_trajectory_file,right_camera_trajectory_file
```

Paths are relative to the session directory. Disabled or inapplicable outputs
produce empty fields. The three trajectory columns repeat their session-wide
file paths in each frame row.

`timestamp_sec` is Unreal world time written with nine decimal places. The
frame index is an integer generated by the capture manager and used directly as
the image/CSV filename stem.

## Trajectories

All trajectory files use:

```text
timestamp_sec,frame_index,frame_id,child_frame_id,x_m,y_m,z_m,qx,qy,qz,qw
```

Positions are ROS-style meters. Quaternions use `x, y, z, w` order. A row is
omitted if its pose source is invalid. Right camera trajectories exist only
when stereo ROS output and trajectory CSV are enabled; left trajectories exist
when stereo ROS or ground-truth camera output is enabled.

## Session metadata

`session_metadata.json` records:

| Object/field group | Contents |
| --- | --- |
| Session | `session_id`, `session_name`, wall-clock `created_at`, capture-output summary, `publish_hz` |
| Camera | image width/height, horizontal FOV, `fx`, `fy`, `cx`, `cy`, `plumb_bob`, five zero distortion coefficients, stereo baseline, left/right projection matrices |
| Frames | `map`, `base_link`, `imu_link`, camera-link, and camera-optical frame names |
| Maps | Enabled flag and run-relative paths for each map artifact |
| Ground-truth outputs | Master enabled flag plus RGB, depth, segmentation, and bounding-box flags |
| Scene | Unreal level name |

It does not record terrain profile, terrain seed, crater settings, rock
settings, Unreal light settings, IMU settings, or external control commands.

## Image encodings

### RGB

Ground-truth RGB is written by UnrealGT as PNG. ROS stereo images use `bgr8`;
the repository does not declare that the offline PNG channel order should be
interpreted as ROS `bgr8`.

### Depth

UnrealGT packs an unsigned millimeter value into the PNG RGB channels:

```text
depth_mm = R + 256 * G + 65536 * B
```

The largest encodable value is 16,777,215 mm. A value of zero is treated as
invalid by the included preview converter. Run:

```bash
python3 Tools/convert_depth.py SESSION_DIRECTORY
```

`SESSION_DIRECTORY` must be an existing `Session_NNN` path. The command writes
8-bit inspection images to `Images/Depth_Greyscale/`; near values are bright
and invalid values are black.

Whether the current ground-truth Blueprint defaults to planar or perspective
depth is **Not yet verified** from the serialized asset. Do not infer the depth
axis model from the encoding alone.

### Segmentation

Per-pixel colors correspond to the generated legends:

- `segmentation_info.json` records object/component names, paths, meshes, tags,
  and RGBA colors.
- `segmentation_classes.json` records format metadata and class IDs, names, and
  RGBA colors.

The exact classes depend on the level and configured UnrealGT components.

### Bounding boxes

Each per-frame CSV uses:

```text
actor_name,mesh_name,min_x,min_y,max_x,max_y,center_x,center_y,extent_x,extent_y,width,height
```

Coordinates are image-space values used by the included drawing script as X
horizontal and Y vertical and clamped to image bounds. The implementation does
not explicitly document the exported pixel-origin convention, so it is
**Not yet verified**.

The visualization command writes `Images/RGB_BoundingBoxes/`:

```bash
python3 Tools/draw_bounding_boxes.py SESSION_DIRECTORY
```

## Map formats

The map publisher automatically derives Landscape bounds and samples at
0.40 m/cell, up to a safety limit of 10,000,000 cells.

| Product | Details |
| --- | --- |
| Occupancy PGM | `0` occupied, `254` free, `205` unknown |
| Occupancy YAML | ROS map metadata with `mode: trinary`, occupied threshold 0.65, free threshold 0.196 |
| Elevation CSV | Meter values or `nan`, stored as a grid |
| Elevation YAML | Grid dimensions, resolution, origin/frame, CSV, and preview association |
| Elevation preview | Display-only grayscale PGM scaled over finite min/max elevation |
| Slope CSV | Grid of slope angles in degrees |
| Slope YAML | Grid dimensions, resolution, origin/frame, CSV, and preview association |
| Slope preview | Display-only grayscale PGM; 45 degrees maps to maximum visualization intensity |

The ROS occupancy values are `-1` unknown, `0` free, and `100` occupied.
Landscape/terrain is identified with `MapTerrain`, obstacles with
`MapObstacle`, and ignored dynamic objects with `MapIgnore`.

## Terrain packages

Terrain artifacts are not copied into the dataset tree:

| Output | Format | Coordinate convention | Main association |
| --- | --- | --- | --- |
| Heightmap | 16-bit PNG | Image origin at top-left; physical size in metadata | Terrain run |
| Generator metadata | JSON | Declares meters, meters/pixel, encoded range, and Unreal import scale | Heightmap |
| Crater catalogue | JSON | Centered X/Y meters | Heightmap and rock generation |
| Rockfield | JSON, `MoonSimOfflineRockField` v1 | `centered_map_meters` | Unreal Rock Baker |
| Rock settings | JSON | Not spatial | Rockfield |
| Source-heightmap record | JSON | Not spatial | Rockfield-to-heightmap provenance |

Each rock record can contain `instance_id`, `x_m`, `y_m`, `diameter_m`, yaw,
tilt, tilt axis, burial fraction, material, placement zone, and source-crater
metadata. Preserve these terrain packages manually with a dataset.

## Synchronization and missing frames

The capture manager gives enabled per-frame modalities and trajectories a
common frame index and world-time stamp. Camera image and CameraInfo ROS
messages from the same capture also share a stamp.

Important limits:

- manifest rows are appended when a frame is scheduled, while image files are
  written asynchronously;
- an invalid pose source can omit a trajectory row;
- IMU, live ground truth, TF, maps, and `/clock` have independent rates;
- there is no automated missing-file, row-count, or timestamp validator.

After capture cooldown, validate that every non-empty manifest path exists and
that required trajectory frame indices are present. Exact automated validation
criteria are **To be documented**.
